- **Copy bandwidth is misnormalized:** [floor.py:92](/home/exedev/bottom-up/link/floor.py:92) divides reads **plus** writes by a benchmark counting only copied payload bytes. Use `2 * DRAM` for that traffic model. Keeping other assumptions unchanged, MinIO’s floors become resolve **2.38 ms**, reach **0.83 ms**, layout **0.41 ms**, write **3.11 ms**; total **6.72 ms**, not **13.15 ms**.

- **Layout charges for dead symbols:** [floor.py:56](/home/exedev/bottom-up/link/floor.py:56) requires addresses and instructions for all 5,205,427 slots. A linker can assign addresses only to 360,376 live symbols. Under the existing four-byte-address model, output is **1.44 MB**, not **20.82 MB**; with normalized bandwidth and live-only instruction count, floor is **0.104 ms**.

- **Reachability uses the wrong edge count:** [floor.py:48](/home/exedev/bottom-up/link/floor.py:48), [floor.py:54](/home/exedev/bottom-up/link/floor.py:54) use *applied* relocations, excluding reachability-only relocations and auxiliary references. Conversely, `2 * AUX` per live symbol is invented. Count actual traversed relocations and aux edges; **0.83 ms above is only a normalization correction**, not a validated reach floor. The stored statistics cannot supply the corrected edge count.

- **Pointer chasing measures a small cycle:** [linklimits.c:159](/home/exedev/bottom-up/hw/linklimits.c:159) builds random successors, not a permutation forming one full-table cycle. The chain quickly repeats a small subset, making large-table load rates too high. Construct a shuffled full-table cycle and remeasure; the reported 64-MB rate even exceeds the 16-MB rate.

- **Random-load throughput includes a serial RNG bottleneck:** [linklimits.c:88](/home/exedev/bottom-up/hw/linklimits.c:88) has six dependent shift/XOR operations between successive indices. Loads are independent of their results, but address generation is serialized, potentially understating hardware throughput and inflating latency floors. Use several independent index streams and remeasure.

- **Re-freezing can retain the old main:** [freeze.sh:24](/home/exedev/bottom-up/link/freeze.sh:24) copies `main.a` only if absent. Normally main is supplied separately from `packagefile` entries, so a second freeze combines old main with new dependencies. Always replace main; also clear obsolete `objs/*.a`.
