# IDEAS (each with a kill test and a status)

| # | idea | kill test | status |
|---|---|---|---|
| 1 | **Output on hugetlbfs, image laid out on 2 MiB boundaries.** The binary execs from `/dev/hugepages` when every PT_LOAD is 2 MiB-aligned in file and memory, filesz = memsz (bss in the mapping) and there are no section headers past the last segment. 55 faults instead of 28,000. | Kill if a 110 MB fill is not under 8 ms on 8 threads, or MinIO's tests do not run from it. | **Built** 2026-11-13 (`-hugetlb`, or -o on hugetlbfs): MinIO process 167-174 ms against 179-182 on ext4; write phase 18-20 ms (fill 3.7, the rest is the copy). Costs: each process run from it reserves huge pages for its whole image (MinIO 67) and dies with SIGSEGV if the pool is short; the file carries its bss (147 MB for 109). Spike: hello (stock link `-R 0x200000`, headers patched) runs from hugetlbfs; `explore/linkos/outfile.c` fills 110 MB in 3.7 ms (tmpfs 19 ms, ext4 31-39 ms). To build: hlink `-hugetlb` layout mode. Needs `sysctl vm.nr_hugepages`. |
| 2 | Overwrite the existing output in place (no O_TRUNC, no unlink): the page-cache pages are already there. | Kill if under 10 ms saved on ext4. | Measured: 13 ms against 31-39 ms (ext4), 9 against 19 (tmpfs). **Built**, default (`-fresh` turns it off): write phase 39-52 -> 14-16 ms. A review found it unsafe against a concurrent link and a kill before the write phase: being replaced by claim-by-rename (mold's protocol). Unlinking a 110 MB tmpfs file costs 11.6 ms by itself. |
| 3 | Return to the caller when the output is complete; tear the address space down in a detached child (what mold does). | Kill if exit teardown is under 3 ms once inputs are mapped sparingly. | fclink's exit costs 56-69 ms here (process minus its own total). **Built**, default (`-nodetach`, `-teardown exit|madvise`): the process returns 3-4 ms after the link's own clock instead of 50. |
| 4 | Linker's own arrays (canon/state/addr, join partitions) from MAP_HUGETLB. | Kill if anonymous-fault kernel time is under 2 ms of the link. | **Built** (hugealloc: MAP_HUGETLB when the pool has pages, else 4 KiB). vm.nr_hugepages raised to 1024. Gain not isolated yet. Anonymous first touch is 4.3 M pages/s on 8 threads: 62 MB of arrays = 3.5 ms. |
| 5 | **Demand-driven resolve fused with reachability**: resolve a reference only when the flood reaches it. By-index references need nothing; content-hashed symbols (2.6 M of MinIO's 5.2 M slots) are interned in a concurrent table only when reached (about 360 k are live); by-name definitions (548 k) are indexed once; a by-name reference to a package-indexed definition builds that package's name index on first miss. | Kill if eager resolve in C is already under 2x its floor (2.4 ms), or if the lazy table's contention makes reach slower than eager resolve + reach. | **Half built, half killed** 2026-11-13. Built: content-addressed symbols joined after the flood (1.29 M reached of 2.68 M, 457 k classes); resolve on one core 152 -> 100 ms, the join costs 33 ms inside deadcode. Killed: lazy by-name references and per-package name indexes; skipping DWARF kinds (4 of 5 by-name references) is exact and removes the same work. Would also lower the resolve floor (not every record must be read), and FLOOR.md must then say so. |
| 6 | One packed input file instead of 1,312 archives (4 ms of opens on 8 threads). | Kill if opens overlap fully with other work. | Not built. |
| 7 | Free input pages with parallel `MADV_DONTNEED` before exit (munmap is single-threaded under the mmap lock, 9.9 M pages/s). | Kill if idea 3 lands. | **Killed** (measured by the builder: 95 ms of kernel CPU, 10-18 ms of wall). |
| 8 | A sidecar index per archive, cached between links (keyed by the archive's content id): symbol flags, sizes, 128-bit name keys and content hashes already laid out for the joins and the flood. Resolve's records pass (60 of its 100 core-ms) becomes a read. | Kill if resolve + reach on one core are under 60 ms without it. Needs Dan: is a cache between links inside "frozen stock objects in, nothing carried over"? | Not built. In STATUS.md for Dan. |
| 9 | Inputs on hugetlbfs: no page-table population (456 MB of metadata is 111 k PTEs), TLB reach of 2 MiB pages, a dependent miss at DRAM latency instead of 158 ns. | Kill if a copy of MinIO's objects on hugetlbfs does not cut resolve + reach by a quarter. An experiment about which limit binds, not a default: the stock compiler cannot write there. | Not tried. |
| 10 | Pre-populate input page tables at load so prefetches are not dropped. | Kill if load grows more than the flood shrinks. | **Killed** 2026-11-13: load 9-12 -> 35-63 ms on 8 threads, flood unchanged. |
| 11 | Layout over the live symbols only: sizeUnit and addrUnit scan all 5.2 M slots and read each live symbol's record twice; keep sizes from the first pass, test liveness on the flag bytes, cache the function shapes that write needs again. | Kill if layout on one core is under 25 ms after the fidelity fixes. | Next. |
