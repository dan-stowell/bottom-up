1. **[P1] Flood instrumentation writes out of bounds with more than 64 workers.** [link/dead.c:571](/home/exedev/bottom-up/link/dead.c:571) indexes `tscStage[64][8]` by worker ID, while `nthreads` has no 64-thread limit. These writes execute even without `HLINK_TSC`. A sufficiently wide frontier with `-j 65` or automatic CPU detection can corrupt memory. Allocate counters by `nthreads` and gate instrumentation.

2. **[P2] Eager decoding resolves references that the flood previously ignored.** [link/dead.c:545](/home/exedev/bottom-up/link/dead.c:545) calls `RREF` for every relocation before `process` filters weak, `R_USETYPE`, `R_INITORDER`, and inactive method edges. `oref` can report a missing package, so an ignored edge can now fail the link. All auxiliary references are similarly decoded, including unused DWARF auxiliaries. Classify edges before decoding; resolve conditional edges only when activated.

3. **[P2, inherited stock-loader mismatch] Selecting a winner loses the larger BSS declaration’s size.** [link/resolve.c:183](/home/exedev/bottom-up/link/resolve.c:183) ranks initialized data above BSS but retains only the winning symbol. Stock Go records size fixups: an initialized 8-byte definition combined with a 32-byte BSS declaration gets the initialized contents and sufficient allocation for the larger declaration. Here layout sees only the smaller definition, potentially allowing accesses to overlap another symbol. Carry effective size separately from the winning ID.

4. **[P2, inherited stock-loader mismatch] Equal-ranked definitions use a different ordering from Go.** [link/resolve.c:260](/home/exedev/bottom-up/link/resolve.c:260) breaks ties by lowest global ID, which follows importcfg/object order. Stock Go loads all package definitions before non-package definitions and retains the earlier definition for equal-sized DUPOK symbols. An earlier object’s non-package DUPOK definition can therefore beat a later object’s package definition here, reversing Go’s winner. Preserve stock loading precedence explicitly in the rank.

5. **[P2, conditional correctness regression] The combined content-hash table does not distinguish hash domains.** [link/resolve.c:219](/home/exedev/bottom-up/link/resolve.c:219) embeds a short hash as `(mix64(h ^ constant), h)` and inserts it into the same table as full 128-bit hashes. A full hash equal to that pair merges unrelated symbols; the old implementation and Go use separate tables. This requires a cross-domain collision—I have not observed one—but a domain tag or separate tables removes the ambiguity completely.

6. **[Performance] The 1,024-symbol scheduling grain serializes substantial frontiers.** [link/dead.c:726](/home/exedev/bottom-up/link/dead.c:726) supplies only one task for up to 1,024 symbols, and four tasks for 4,096 symbols. Symbol count also poorly predicts relocation work. Schedule batches by edge budget, split large adjacency lists, and consume worker-local frontier segments through a shared task directory. This also removes the serial per-symbol frontier concatenation at lines 719–721.

7. **[Performance] Staging still repeats metadata work and leaves irregular traversal in the final stage.** [link/dead.c:639](/home/exedev/bottom-up/link/dead.c:639) passes only target arrays to `process`, which recomputes object/symbol mapping and relocation/auxiliary ranges already available in the batch. It also repeats FuncInfo discovery and performs interface/type lookups synchronously. Pass the prepared descriptor directly; compact ordinary strong edges into a marking stream and handle reflection/method edges separately. Budget batches by edges so large symbols do not overwhelm the prefetch window.

8. **[Performance] The joins retain dependent probes, redundant passes, and shared atomic updates.** [link/resolve.c:293](/home/exedev/bottom-up/link/resolve.c:293) follows `idx → ent` for each probe, rebuilds another table, and later re-probes every name record. Package definitions then update shared winners using CAS at line 384. Keep per-list counts, retain group IDs, batch independent probes, and route matching package definitions to their partition owner for local reduction. Worker-local Bloom filters followed by an OR reduction would also eliminate shared atomic Bloom updates.
